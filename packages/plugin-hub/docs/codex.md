# Codex worker adapter

`adapter = "codex"` uses Codex App Server's existing agent engine through the shared Hub adapter interface. Jobs keep their own Hub conversation and explicit follow-ups resume its mapped Codex thread. Progress, final answers, usage, receipts and explicit stops use the normal runner lifecycle; Hub does not implement another model/tool loop.

The protocol is bound to CLI `0.160.0`, with the installed build checked before preparation and again at initialization. Official references: [App Server](https://learn.chatgpt.com/docs/app-server), [configuration](https://learn.chatgpt.com/docs/config-file/config-reference), [feature flags](https://learn.chatgpt.com/docs/config-file/config-basic), and [MCP](https://learn.chatgpt.com/docs/extend/mcp). The generated schema and real local binary establish the exact wire spellings; examples on the website may describe a different build.

Use an explicit preset model, provider, effort and `model-key` credential (`paid = "key"`). `openai` defaults to `https://api.openai.com/v1`; another provider needs its explicit Responses-compatible `base_url`. This initial adapter does not import a ChatGPT login, change accounts, or infer a model. Model/provider mismatches fail. Credential bytes enter the engine environment, never generated config or argv. The configured credential file remains masked by the existing Hub box.

Each conversation has an isolated HOME/CODEX_HOME and an atomic, fsynced Hub-to-Codex thread mapping. Native delegation, goals/automatic continuation, apps, plugins and user hooks are disabled and the effective configuration is checked. Shared person instructions and stdio MCP configuration are retained, including the conversation-bound Hub facade. Unsupported custom tool lists, settings translations, remote MCP shapes, triage and harvest launches refuse explicitly rather than weakening their restrictions. Codex's own sandbox is disabled only inside the required existing outer Hub box; the adapter never omits that wrapper.

Normal completed-turn continuation is supported. A dirty marker precedes every input write; failed, interrupted, disconnected or unverified histories cannot resume. `safeResume` stays false: no interrupted-tool replay guarantee is claimed. An empty thread is not materialized by this Codex build; only a durable `sent=false` mapping permits recreating that empty thread. Once any input may have been sent, missing state never falls back to a fresh thread. Thread token-counter deltas are used when available; missing usage stays null. Resolved backend model identity is not invented from the configured model.

## Validation and platform limits

Synthetic protocol/launch tests and a real Hub worker/store integration cover conversation isolation and explicit continuation. The real macOS CLI completed two turns with a process restart and executed a synthetic Hub MCP tool against a loopback-only Responses fixture. That used fake credentials, no paid model, and no live provider. Neither native delegation nor goal tools were advertised under the prepared config.

The macOS startup failure (`Failed to synchronize managed preferences`) is resolved by a Codex-only read grant for the exact OS shared-memory names `apple.cfprefs.<uid>v1` and `apple.cfprefs.daemonv1`. Both were required by the actual 0.160.0 binary; either alone failed before initialization. No preference-domain, preference-directory, credential, shared-memory write, or new host-control access is granted. Other adapters retain their prior profiles. The [managed configuration](https://learn.chatgpt.com/docs/enterprise/managed-configuration) mechanism itself is still honored; no managed-policy bypass is used. The diagnostic `codex-managed-preferences-unavailable` remains for unavailable configurations.

`bun live/prove-codex-box.ts --bin /absolute/path/to/codex` runs the actual pinned engine through the production outer box using a synthetic loopback Responses provider. It proves initialization, two completed turns across a process restart, Hub MCP execution, masked credential and other-person files, and confirmed process exit. It does not accept an unboxed mode, paid key, or remote endpoint. The proof uses disposable state only. The measured Mac runtime was Hub's Bun 1.3.14; Homebrew Bun 1.3.10 lost custom environment entries in the boxed Bun MCP child and failed this proof, despite the boxed shell retaining them. Use the measured runtime; no sandbox permissions were added for that separate runtime discrepancy. This is boxed protocol/tool evidence, not model quality, account entitlement, interrupted-turn recovery, or a production rollout. The Pi's installed CLI is 0.151.0 and remains rejected by this adapter's 0.160.0 pin, so Linux activation is not claimed.

No native transfer port is supplied. OpenCode retains its existing measured session-store/delegation capabilities and `safeResume=false`; its persisted sessions and successful ordinary continuation do not prove interrupted-tool replay safety. The movement lane separately retains the explicit missing-port refusal. No Claude or OpenCode behavior was changed by this adapter.
