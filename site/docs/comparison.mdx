Most AI-memory tools build a store for the **machine** to read: a vector index you cannot open. imprnt builds plain notes for **you** to read, that the AI also searches. This page shows where that helps and where it does not.

The field is crowded and mostly well built. The marketing all reads the same ("never forget", "your AI second brain", "local-first"), so the labels will not tell you which to use. What separates these tools is the **architecture** underneath, and it points in opposite directions from one to the next.

## The one question that splits the field

Almost every tool here sorts on a single question: **is the memory built for the machine to read, or for you to read?**

## No lock-in

Most tools here bind your knowledge to a store you do not control. The few that keep plain files still wrap them in a derived index or a server. imprnt is the one that keeps both the files and the search portable.

## imprnt's four bets

Each is the minority position in the field.

<Bets />

imprnt's white space is **plain Markdown the AI reads directly, BM25 and grep, no vector DB, no server.** It pays off when BM25 over a well-tagged vault answers the questions you actually ask. It loses when your queries need vector recall over raw, untagged text. The benchmark section below makes that tradeoff concrete.

## The field at a glance

Facts are pulled from each project's own README and docs (checked 2026-06-18). Benchmark numbers are **self-reported** by the vendor under its own harness, so read them as "the project claims X", never a settled leaderboard. The numbers are contested even among the vendors: Zep published a rebuttal of mem0's headline LoCoMo claim, mem0 fired back disputing Zep's, the clearest public sign these scores are not neutral.

<CompareTable />

Posture on cloud varies. mem0, Zep, and Supermemory are cloud-first with a local mode. Letta, cognee, mempalace, and iai self-host, and Khoj is self-host only after closing its cloud in 2026. Obsidian and Logseq are local apps with optional paid sync. Karpathy's LLM Wiki and imprnt have no hosted mode and no account, because the files are already on your disk.

Logseq shows how fast this moves. Its original version keeps your notes as plain Markdown you can grep and edit by hand. The new default stores them in a local SQLite database and treats Markdown as an export. If owning plain files is the reason you picked a tool, check which version you are on before you rely on that.

## The closest kin: Karpathy's LLM Wiki

<ClosestVerdict
  same="The three-layer design: raw sources, an LLM-compiled wiki, a schema."
  deltaLabel="imprnt adds"
  delta="A BM25 ranker and a typed entity contract."
/>

In design, [Karpathy's LLM Wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f) is imprnt's nearest relative. Same three layers: immutable raw sources, an **LLM-compiled** Markdown wiki, and a `CLAUDE.md` schema. Same `index.md` catalog and append-only `log.md`. No embeddings, the LLM reading the index then full pages. The LLM as a **compiler** that reads a source once and writes durable pages. The agent reading files directly, no server. imprnt sits in that lineage.

Where imprnt goes further:

- A deterministic **BM25 ranker** over title, tags, and body, so recall does not lean on the LLM re-reading the whole index, and it holds up past a few hundred notes.
- A typed **entity contract** (people, orgs, holdings, with aliases and canonical resolution), so the same person never splits into two pages.
- A shipped **CLI** plus a plugin system, rather than a pattern you assemble by hand.

Karpathy's gist validates the bet. imprnt is the same bet with more structure on top, and a ranker in place of index-reading.

## The closest shipped tool: Basic Memory

<ClosestVerdict
  same="Markdown is the source of truth, captured on a deliberate write."
  deltaLabel="it differs on"
  delta="A derived SQLite index and an MCP server between the AI and the files."
/>

Among finished products, Basic Memory shares imprnt's floor. It treats Markdown as the source of truth, keeps a derived SQLite index in sync, and captures on a deliberate write. If you want imprnt's "own your files" stance with a conventional MCP-server delivery, it is a real and good choice.

The split is downstream of **storage**. Basic Memory defaults to hybrid vector search and puts a derived database and an MCP server between the AI and the Markdown. imprnt removes that layer and has the AI grep the files with BM25, the model touching only the two ends of a query. Same respect for the file, opposite call on the machinery around it.

## What the benchmark numbers mean for you

<BenchStrip />

LongMemEval scores recall over **auto-logged conversation dumps.** A model captures thousands of raw turns, and the test asks whether the right turn can be found again. It measures a real task. If your use is "remember everything from every chat and surface it later," it is the number to trust, and a tool like mempalace or iai is your pick.

imprnt is built for a different task: retrieval from a small set of notes you curated, typed, and linked on the way in. The corpus is smaller and cleaner because the judgment happened at **write time**, not in a vector search at read time. Its own eval runs plain-language questions against the curated example vaults and checks where the answer note ranks. The corpus is small and the questions are hand-written, so read the 90% / 97% as an early **indication** that BM25 over a tagged vault answers the questions asked, not a leaderboard entry. The harness and queries live in [`eval/`](https://github.com/aleksandr-bogdanov/imprnt/tree/main/eval) so you can run it yourself.

If a big-corpus leaderboard score is what you need before committing, pick a tool that publishes one.
