Out of the box, an assistant writes like an assistant. **Anti-slop** is a fixed set of rules you hand it so the tells go away.

Those tells are easy to spot once you know them: em-dashes, filler like `robust` and `seamless`, openers like `it's worth noting that`, the negate-then-affirm rhythm (<span class="antislop-nowrap">`this isn't X, it's Y`</span>). The rules ban them across every bit of prose the assistant produces, whether a vault note, a doc, a message, or a deliverable.

<AntiSlopBeforeAfter />

## What it bans

A **behavior** plugin. It hands the assistant a fixed chunk of text you wire into its prompt. No code, no commands, no data, and it never touches the vault. The rules fall into four categories.

<AntiSlopCategories />

## Install

Wire the rules at one of two **scopes**. Project scope reaches this repo only. User scope reaches every `imp` session, in any directory, while a plain `claude` session stays untouched (imprnt only shapes sessions it launches). The user-scope add promotes the copy the project add installed, so run the project add first, or pass `--from <dir>` to promote any folder holding the fragment. The matching remove is the off switch, and the assistant goes back to its default voice.

<AntiSlopInstall />

### Make the rules your own

To run your own register and banned words on top, copy the fragment into the private `_personal/` folder, extend it, and wire that copy instead. The `_` prefix keeps the folder out of `plugin list`, so your overlay never lands in the public gallery. If you ever git-init your vault project, add `plugins/_personal/` to its `.gitignore` so it never ships.
