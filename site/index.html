A knowledge vault you own and run locally.

imprnt keeps what you know in plain markdown files on your disk. You talk to your assistant, it files what matters, and weeks later it answers from your real history.

npm i -g imprnt && imprnt init Get started

The LLM builds the tools. The tools do the work.

The problem

Your assistant starts every chat blank. You re-explain your projects, your people, and your decisions every time, and whatever it learns dies with the session. The fixes on offer hide your knowledge in a vector database or a memory feature you can neither read nor switch off.

imprnt keeps the part that lasts in files you can open in any editor. Reads run on cheap local code, so your assistant can lean on your whole history every session, and no company can take it away.

How it works

imprnt rations the model by where it runs. Understanding a messy source is worth the model, and it happens once. Searching happens thousands of times, so it stays plain local code. Frequency draws the line.

Write once, with judgment

When you save a transcript or a doc, the model reads it, picks the note type, writes a one-line summary, pulls out decisions, assigns tags, and wires links to people and projects. This is the conscious work, and it runs one time per source.

Read with grep and BM25

recall ranks your notes with BM25, a 1990s term-frequency formula that is pure local arithmetic. No model in the loop, no embeddings, no server. The model shapes your question into keywords at the front and reads the top hits at the back.

Plugins you rm -rf

The core is your vault plus three commands. Every other behavior is a plugin you add by asking and remove with one line plus rm -rf. The core never knows a plugin exists, so it stays small.

Why it's different

imprnt does nothing until you run a command. You own the files, and the off switch is real.

Own your files

Plain text on your disk, owner-only and local. It opens in any editor, graphs in Obsidian, and traces every note back to its source. The vault is the version of record.

No daemon, no cloud

No always-on hooks, no auto-injected context, no background loop, no cloud sync, no dashboard to feed. The model never takes an action you did not approve.

Opt in, then compose

A fresh setup loads zero plugins. You add the ones you want, one at a time, and delete the line to turn one off. It composes, and you compose it.

Cheap, honest reads

A lookup costs about 100 tokens of local ranked search. The same query through a vector database or an MCP server costs far more and goes stale on every edit.

Quickstart

Install the engine your assistant drives, scaffold a vault, and talk. Runs on Node 18 or newer.

  1. Install and init

    Scaffold the vault and drop the CLAUDE.md contract your assistant reads.

    npm i -g imprnt
imprnt init

  2. Open the front door

    Type imp instead of claude in any directory. Stock claude stays stock.

    imp

  3. Ingest a source

    Hand your assistant a transcript, a doc, or a single fact. It files structured, linked notes.

    You: Save this transcript and file what matters.
     [paste or drop the source]

  4. Recall what you know

    Ask in plain language. recall ranks your notes and answers from the top hits.

    You: What did we decide about the access-platform cutover?

  5. Add a plugin when you need one

    Each plugin is its own package. Add it by name, remove it with the same command.

    imprnt plugin add anti-slop
imprnt plugin rm anti-slop
